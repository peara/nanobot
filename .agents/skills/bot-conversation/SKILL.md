## What I do

I enable Sisyphus (AI agent) to communicate directly with nanobot through the FileChannel interface using JSONL files. This allows me to debug issues, test new features, and perform end-to-end workflows without external interfaces.

## When to use me

Use this when:
- Debugging bot behavior by sending test messages
- Testing new features end-to-end
- Investigating how bot processes specific queries
- Verifying tool call sequences and responses
- Running automated E2E tests
- Checking if tools work correctly with real inputs

## Key Principles

### 1. FileChannel uses separate in/out directories
- Input: Write user messages to `data/chat/sessions/in/{session_id}.jsonl`
- Output: Read responses from `data/chat/sessions/out/{session_id}.jsonl`
- Separate files prevent concurrent write conflicts

### 2. Sessions are auto-generated by the bot
- Bot creates `session_{timestamp}_{random4}` on startup
- Session lifecycle: `session_start` on bot start → `session_end` on bot stop
- To find active session: read `out/` for `session_start` without `session_end`

### 3. JSONL event format (append-only log)
Each line is a JSON object with a `type` field:
- `session_start` — bot started
- `user_message` — incoming message from user
- `tool_call` — LLM calling a tool (captured by FileTraceHook)
- `tool_result` — tool execution result
- `assistant_message` — bot's reply
- `turn_complete` — signals response is complete
- `session_end` — bot stopped

### 4. FileTraceHook requires `capture_tool_calls: true` in config
Enable in `config.yaml`:
```yaml
channels:
  - type: file
    options:
      capture_tool_calls: true
```

## Common Patterns

### Discover active session
```bash
# Find the most recent session_start without session_end
ls -t data/chat/sessions/out/*.jsonl | head -1 | xargs head -1 | jq -r '.session_id'

# Or check all sessions
for f in data/chat/sessions/out/*.jsonl; do
  if head -1 "$f" | jq -e '.type == "session_start"' > /dev/null 2>&1; then
    if ! grep -q '"type": "session_end"' "$f" 2>/dev/null; then
      basename "$f" .jsonl
    fi
  fi
done
```

### Send a message to the bot
```bash
SESSION_ID="session_20260502_163630_kmdo"
MESSAGE="what's the weather in Bangkok?"
USER_ID="sisyphus"

# Append user_message to in file
echo "{\"type\": \"user_message\", \"text\": \"$MESSAGE\", \"user_id\": \"$USER_ID\", \"timestamp\": \"$(date -Iseconds)\"}" >> "data/chat/sessions/in/$SESSION_ID.jsonl"
```

### Wait for response (polling pattern)
```bash
# Poll for turn_complete, then extract assistant_message
SESSION_ID="session_20260502_163630_kmdo"
OUT_FILE="data/chat/sessions/out/$SESSION_ID.jsonl"

# Wait until turn_complete appears (with timeout)
timeout 180 bash -c "
  while ! grep -q '\"type\": \"turn_complete\"' \"$OUT_FILE\" 2>/dev/null; do
    sleep 0.5
  done
"

# Extract assistant response
grep '"type": "assistant_message"' "$OUT_FILE" | tail -1 | jq -r '.text'
```

### Watch tool calls in real-time
```bash
# Monitor out file for tool_call and tool_result events
SESSION_ID="session_20260502_163630_kmdo"
tail -f "data/chat/sessions/out/$SESSION_ID.jsonl" | while read line; do
  TYPE=$(echo "$line" | jq -r '.type')
  case "$TYPE" in
    tool_call)
      TOOL=$(echo "$line" | jq -r '.tool')
      ARGS=$(echo "$line" | jq -c '.args' | head -c 80)
      echo "🔧 $TOOL $ARGS"
      ;;
    tool_result)
      OK=$(echo "$line" | jq -r '.ok')
      PREVIEW=$(echo "$line" | jq -r '.result_preview' | head -c 100)
      echo "$([ \"$OK\" = \"true\" ] && echo '✓' || echo '✗') $PREVIEW"
      ;;
    assistant_message)
      echo "📤 Response received"
      ;;
    turn_complete)
      echo "✅ Turn complete"
      ;;
  esac
done
```

### Read full response with tool trace
```python
# Python helper to read complete session output
import json
from pathlib import Path

def read_session(session_id: str) -> dict:
    out_file = Path(f"data/chat/sessions/out/{session_id}.jsonl")
    events = []
    for line in out_file.read_text().splitlines():
        if line.strip():
            events.append(json.loads(line))
    
    return {
        "session_id": session_id,
        "events": events,
        "tool_calls": [e for e in events if e.get("type") == "tool_call"],
        "messages": [e for e in events if e.get("type") in ("user_message", "assistant_message")],
        "response": next((e["text"] for e in reversed(events) if e.get("type") == "assistant_message"), None),
    }
```

## Complete Workflow Example

When debugging or testing:

1. **Find active session** (or check config.yaml for `session_id`):
   ```bash
   SESSION_ID=$(ls -t data/chat/sessions/out/*.jsonl | head -1 | xargs basename .jsonl)
   ```

2. **Send test message**:
   ```bash
   echo "{\"type\": \"user_message\", \"text\": \"test query\", \"user_id\": \"sisyphus\", \"timestamp\": \"$(date -Iseconds)\"}" >> "data/chat/sessions/in/$SESSION_ID.jsonl"
   ```

3. **Monitor tool execution**:
   ```bash
   tail -f "data/chat/sessions/out/$SESSION_ID.jsonl"
   ```

4. **Wait for response**:
   ```bash
   # Block until turn_complete
   while ! grep -q '"type": "turn_complete"' "data/chat/sessions/out/$SESSION_ID.jsonl"; do
     sleep 0.5
   done
   ```

5. **Extract result**:
   ```bash
   grep '"type": "assistant_message"' "data/chat/sessions/out/$SESSION_ID.jsonl" | tail -1 | jq -r '.text'
   ```

## Configuration Checklist

Before using FileChannel:

- [ ] Bot is running with `file` channel in config.yaml
- [ ] `sessions_dir` path exists (default: `./data/chat/sessions`)
- [ ] `capture_tool_calls: true` for tool trace visibility
- [ ] In/out directories created (`sessions/in/` and `sessions/out/`)
- [ ] Session has started (check for `session_start` event in out file)

## Scope Convention

- FileChannel uses scope: `file:{session_id}`
- Example: `file:session_20260502_163630_kmdo`
- This appears in tool call events and context storage
